# 人脸预览与单方式启用

菜单 3 → 管理人脸 → 新增，打开本地 GTK3 预览窗口。上方使用前置彩色摄像头供调整姿态；自动优先选择与红外节点属于同一物理摄像头组件的彩色节点，多个候选时询问用户。下方仍是 Biopass 从红外摄像头检测到的实际裁剪。彩色图像不参与样本保存和身份匹配。

检测到第一张有效候选后，画面与样本冻结、确认按钮保持可用，不再两秒过期。可以“确认录入”“重新截取”或“取消”。重新截取放弃旧候选并恢复预览。它表示检测到人脸，不表示身份匹配或活体检测。当前未提供原画面定位框。

确认才写入本人私有 faces 目录；取消不保存。预览 JPEG 留在内存，未确认的候选裁剪仅临时保存在 /dev/shm 并清理，不上传照片或视频。需要 python3-gi、gir1.2-gtk-3.0；准备清单已加入后者。

旧脚本无预览、连续快速尝试 12 次后退出，无法区分暗画面与姿态问题。新版持续读取预览并预热 2 秒，然后不断检测，用户可看图调整；没有降低检测或认证阈值。机主已在临时 Zorin 系统确认人脸录入和新版预览交互可用。

如果仍检测不到：画面太暗或全黑，优先检查红外照明、摄像头隐私开关及选定节点；画面清晰但没有裁剪，检查距离、完整正脸、模型兼容性。助手初始化、采集或模型错误会直接显示在窗口，不再统一伪装为姿态问题。请勿公开带有本人面容的调试图像。

菜单 5 现在允许仅人脸、仅指纹、两者同时启用：根据已有样本设置各方法 enable 开关，独立测试只要求当前选中的方法和密码。只有指纹时无需先录人脸。后续添加另一种，重新运行菜单 5，会保留第一次 PAM 原始备份；若 PAM 后来被其他软件修改则拒绝覆盖。原密码保留。

从仅指纹改为人脸时，菜单 3 会补齐相机/模型配置，不必卸载重装。如果缺 GTK3 预览依赖，可在临时系统先执行 `sudo apt-get install --no-remove python3-gi gir1.2-gtk-3.0`，不会修改 Windows Hello。
